# Release safety

The native release workflow is `.github/workflows/linux-release.yml` (workflow name: Native release). Dispatch it with a full lowercase commit SHA and `validate` or `publish`. Validation works from a feature branch; publication is restricted to dispatches from `main`. Dispatch **Native release** with a full lowercase SHA and `mode=validate`; publication requires `mode=publish` and a new matching tag (`v0.minor.patch` or `v1.0.0-rc.N`). For example: `gh workflow run linux-release.yml --ref main -f sha=<40-character-commit-sha> -f mode=validate`, then repeat with `-f mode=publish -f tag=v0.4.3`. Both Linux amd64 and macOS arm64 jobs build the requested SHA, run checks, and retain checksummed artifacts. Publication revalidates hashes, source SHA and package/bundle metadata, then creates an annotated tag and publishes the package, archives, SHA256SUMS and SOURCE_SHA files. The write-enabled job does not check out or execute source. Existing tags and network errors fail closed. RC tags such as `v1.0.0-rc.1` are published as prereleases, not latest releases. Validation does not tag, publish, or change versions.

The Linux target is an Ubuntu 24.04 amd64 `.deb`. Build prerequisites are Vulkan, X11, xcb, XKB, freetype and fontconfig development packages, as listed in `.github/workflows/ci.yml`. `scripts/package-linux-deb.sh` derives ELF shared-library dependencies using `dpkg-shlibdeps`, converts SemVer prereleases to Debian `~` ordering and verifies package contents. The workflow mounts only the built `.deb` and readonly smoke script in a fresh Ubuntu 24.04 Docker container. The container installs runtime/test packages (no `-dev` packages), installs the app, and launches as `nobody` with isolated HOME and XDG_RUNTIME_DIR under Xvfb. `libvulkan1` is explicitly in the package dependency list because Vulkan may be loaded dynamically and thus absent from ELF `DT_NEEDED`; lavapipe is a smoke-test dependency. This proves runtime startup, not pixel rendering or distribution across other Linux releases. Manual acceptance remains: inspect artifacts from a validate dispatch and confirm the app's rendering/interaction on supported real desktops before publishing.

Use Rust 1.97.1. `scripts/release.sh check` runs formatting, clippy, workspace tests, and RustSec plus release-script tests. `scripts/release.sh build` also builds the optimized app. On macOS, `scripts/release.sh release` assembles the local `.app`; it does not publish, sign for distribution, notarize, or tag.
